# Аудит Anteyko: критика мирового уровня

Полный разбор по дизайну, UX, UI, точности и мелочам.

---

## 1. Критические ошибки (блокеры)

### 1.1 Мёртвые ссылки
- **Footer:** ссылки на `/privacy` и `/terms` — страниц не существует → 404, потеря доверия.
- **Contact:** «Submit another request» и кнопка «Scoping call» ведут на `href="#"` с `preventDefault` — семантически пустая ссылка; при отключённом JS или для ботов бесполезна.

### 1.2 Отсутствующие ресурсы
- **Layout** ссылается на: `/og-image.png`, `/icon.svg`, `/apple-touch-icon.png`, `/manifest.json`.
- В `public/` их нет → 404 в консоли, пустые превью в соцсетях и мессенджерах.

### 1.3 SEO и доступность
- **`<html lang="en">`** захардкожен. При переключении на RU язык страницы не меняется → неверный `lang` для скринридеров и поисковиков.
- **Metadata:** `verification.google: "your-google-verification-code"` — плейсхолдер; при подключении Search Console будет ошибка.

## 2. UX

### 2.1 Контактная форма
- После успешной отправки «Submit another request» — ссылка `#`, не кнопка; для формы логичнее `<button type="button">` или сброс через кнопку.
- Текст «Prefer a call? Book a 20-minute scoping call (link editable in code)» — упоминание «editable in code» не должно попадать в прод; плюс ссылка снова `#`.
- Нет явного сообщения об успехе для скринридеров (live region, `aria-live="polite"`).

### 2.2 Навигация
- Нет «Skip to main content» — клавиатурные пользователи вынуждены проходить все пункты меню.
- Мобильное меню: при открытии фокус не переносится в меню и не ловится внутри (focus trap) → при Tab фокус может уйти «под» overlay.

### 2.3 Язык
- Переключение EN/RU не сохраняется (нет cookie/localStorage) → при переходе по страницам или обновлении язык сбрасывается.

### 2.4 CTA
- Hero и Final CTA: «Get an estimate in 48 hours» и «Book a 20-min scoping call» — обе ведут на `/contact`. Второй CTA не ведёт на календарь/внешний слот → ожидание пользователя не совпадает с поведением.

## 3. UI и визуал

### 3.1 Консистентность
- Hero: заголовок с `gradient-text` (фиолетовый градиент), остальные секции — сплошной `text-text-primary`. Для премиума ок, но на очень тёмном фоне контраст градиента стоит проверить по WCAG (AA).
- Кнопки: в Hero используется `Button` с `onClick` → `window.location.href`, в других местах — `ButtonLink`. Разный подход (редирект vs Next Link) → нет префетча, чуть хуже для восприятия скорости.

### 3.2 Hero и 3D
- Обёртка 3D сцены с `scale` через Framer Motion: при scale &lt; 1 могут быть тонкие артефакты/дрожание на некоторых устройствах; `transform-origin: center` по умолчанию — ок, но при очень быстром скролле стоит проверить.
- Градиент поверх сцены (`from-bg-primary/20 ... to-bg-primary`) — хороший баланс; стоит убедиться, что белый текст на градиенте даёт контраст ≥ 4.5:1.

### 3.3 Типографика
- В hero подзаголовок только `text-body-lg` — на больших экранах может выглядеть мелко относительно заголовка 4.5rem.
- Нет явного ограничения длины строки (max-width по символам) для длинных параграфов — на ультрашироких мониторах строки могут быть слишком длинными для комфортного чтения.

### 3.4 Секции и отступы
- Чередование padding (lg / xl) есть — хорошо. Варианты `xl-top` и `compact` в коде есть, но на главной не используются — можно применить для разнообразия (например, FAQ compact).

## 4. Код и точность

### 4.1 Форма
- Honeypot поле `website`: скрыто через `absolute -left-[9999px]` — классика, но `aria-hidden="true"` на обёртке есть; у внутреннего `input` нет `aria-hidden`, скринридер может его найти (лучше добавить `aria-hidden` на сам input или оставить только визуально скрытым с сохранением доступности для ботов).

### 4.2 API
- Contact API пишет в `data/leads.json` без валидации email (формат), длины полей, санитизации — риск переполнения и некорректных данных.
- Нет rate limit — форма уязвима к спаму запросами.

### 4.3 Данные и переводы
- В переводах и кейсах в основном консистентная структура; в артефактах кейса 1 текст захардкожен на EN («Integration Test Catalog», «Pre-deployment checklist», «RPC / wallet matrix») — при выборе RU подписи остаются на английском.

### 4.4 Компоненты
- `TiltCard`: для шума при hover используется CSS-переменная `--noise-opacity` на родителе; значение задаётся числом (0.05), в Tailwind arbitrary value `opacity-[var(--noise-opacity)]` — корректно.
- `AnimatedItem`: при использовании `whileInView` и `viewport={{ once: true }}` элементы не реанимируют при повторном появлении в зоне видимости — ожидаемо.

## 5. Мелочи и полировка

### 5.1 Семантика
- `<main>` в PageWrapper один — ок. У секций нет явных `<article>` там, где уместно (например, кейсы, FAQ) — не критично, но улучшило бы структуру.
- Footer: блок с навигацией — `<nav>`, контакты — просто div; можно обернуть контакты в `<address>` для семантики.

### 5.2 Микро-копия
- Hero trust line: «Milestone-based delivery» (EN) vs «Работаем по этапам» (RU) — смысл совпадает.
- Contact success: «Optional: book a 20-minute call» — «Optional» может размывать призыв; можно усилить формулировку.

### 5.3 Производительность
- 3D сцена (Three.js) подгружается динамически — хорошо. На слабых устройствах можно было бы снижать качество (меньше частиц) по `prefers-reduced-motion` или по данным устройства (не реализовано).
- Шум (noise overlay) — один глобальный div с SVG data URL; тяжёлым не является.

### 5.4 Консистентность кнопок
- В шапке CTA — `Button` + `onClick` → `window.location.href`.
- В Hero — то же.
- На странице контактов после успеха — `<a href="#">` с preventDefault.
- Лучше везде использовать Next.js `Link` или `ButtonLink` с `href="/contact"` для единообразия и префетча.
